# crudding

Interactive CLI written in Go 1.27 that generates projects from templates embedded in the executable.

![App Screenshot](docs/assets/panel.svg)

## Install the `crudding` Command

```sh
make install
```

## Run

After the instalation you can use the command "crudding" to create a new project 

```sh
crudding
```

Use the arrow keys to navigate, Space to select, and Enter to continue. Choose Python, Go, or Node, then select a framework and architecture. Python architectures are `flat`, `layered`, `modular`, `hexagonal`, and `clean_arch`. Go architectures are `flat`, `layered`, `modular`, `hexagonal`, and `clean arch`. Node frameworks are `raw`, `express`, `fastify`, and `nest`; its architectures are `flat`, `layered`, `modular`, `hexagonal`, and `clean_arch`. Also choose JavaScript (`js`) or TypeScript (`ts`). Before generating the project, crudding prompts for a name and creates a directory with that name in the current working directory. Existing directories are never overwritten. Press `q` or Esc to exit.

Template files are compiled into the executable, so no templates are downloaded during project generation. To install dependencies, follow the README generated for the project: Python uses `python -m pip install -r requirements.txt`, Go uses `go mod tidy`, and Node uses `npm install`.

Every generated project contains a `project.crud` file at its root recording how it was generated and listing its structure, in the same format written by `crudding init` (see [Custom Templates](#custom-templates)):

```json
{
  "version": 1,
  "name": "my-api",
  "language": "python",
  "framework": "fastapi",
  "architecture": "modular",
  "endpoints": [],
  "endpoint": { "name": "", "files": [], "register": [] },
  "ignore": [],
  "directories": ["src", "src/app"],
  "files": [".gitignore", "README.md", "requirements.txt", "src/app/main.py"]
}
```

## Add an Endpoint

```sh
cd my-api
crudding add endpoint
```

crudding looks for `project.crud` in the current directory or any parent, asks for the endpoint name (snake_case, e.g. `invoice`, `order_item`) and creates it from the `endpoint` field of `project.crud`. It copies the files of the project's model endpoint, replacing its name, and registers the copy next to the model's registration lines (see [Custom Endpoints](#custom-endpoints)). There is no per-architecture code for this: projects generated by crudding come with the field already pointing to the model endpoint they include (`user` in Go, `resource` in Python), so a new endpoint is a working copy of it. Existing files are never overwritten, and if anything fails no change is kept.

Works for every Python and Go architecture and framework. Node projects come with the `endpoint` field empty, so the command asks you to fill it in.

## Remove an Endpoint

```sh
cd my-api
crudding remove endpoint <name>
```

Undoes `crudding add endpoint`: removes the copies of the model endpoint and their registration lines, and updates `project.crud`. The model endpoint itself cannot be removed.

## Add Database

```sh
cd my-api
crudding add db <postgres|mysql|mongo>
```

Adds database connection setup to your project:
- `docker-compose.yml` for containerized databases (`postgres`, `mysql`, and `mongo`);
- `.env.example` with connection environment variables;
- `migrations/` directory with initial migration scripts;
- Language-specific driver connection helper (`db.go` for Go, `database.py` for Python, `database.js`/`database.ts` for Node);
- Updates `requirements.txt` (Python) or `package.json` (Node) with the required database driver dependencies.

## Custom Templates

Any project can become a template: crudding records its structure in `project.crud` and copies it into new projects.

```sh
cd my-template
crudding init                                # writes project.crud with the project structure
cd ..
crudding template ./my-template my-api       # or: crudding template ./my-template n:my-api
```

`crudding init` writes a `project.crud` in the current directory listing every folder (`directories`) and file (`files`) of the project, except what matches `ignore`:

```json
{
  "version": 1,
  "name": "my-template",
  "language": "",
  "framework": "",
  "architecture": "custom",
  "endpoints": [],
  "endpoint": { "name": "", "files": [], "register": [] },
  "ignore": [],
  "directories": ["cmd", "cmd/api", "internal", "internal/health"],
  "files": [".gitignore", "README.md", "cmd/api/main.go", "go.mod", "internal/health/handler.go"]
}
```

- `name` defaults to the folder name and is what gets replaced in new projects. You may fill in `language` and `framework`; they are shown by `crudding info`.
- `ignore` starts empty: crudding never fills it for you, not even from `.gitignore`. Add what should stay out (e.g. `["node_modules", ".venv", ".env", "*.log"]`) and run `crudding init` again. It supports a subset of the gitignore syntax: `*`/`?`/`[...]` globs, a trailing `/` and a leading `**/`. A pattern containing `/` matches the whole path from the root (`/api` is only the root `api`), and one without `/` matches any file or folder with that name. Negations (`!pattern`) are not supported. `.git` folders are never listed.
- Run `crudding init` again after adding or removing files by hand: it regenerates `directories` and `files` and keeps everything else, including your edits to `ignore`. `add endpoint`, `remove endpoint` and `add db` update both lists with the files they create or remove.
- Projects generated by crudding already list their structure, so they can be used as templates right away.

`crudding template <folder> [name]` creates `./<name>` with exactly the listed folders and files. It asks for the name when it is not given. Files present in the template but missing from `files` (and not ignored) are reported, not copied. The template's `name` is replaced by the new name in paths and in the content of text files (binary files are copied as they are):

- the exact form (`My Template`) becomes the name you typed;
- kebab-case (`my-template`) and snake_case (`my_template`) become the same forms of the new name;
- for one-word names, where both forms are the same, the new snake_case is used, since it stays valid as a Python package or Go module.

Choose a distinctive `name`: a generic one such as `api` would be replaced everywhere.

The new project's `project.crud` is a copy of the template's, with the new `name`, `"template": "<template name>"` and the renamed paths, so it can be used as a template too. `crudding add db` is not supported for `"architecture": "custom"`. A template made from a crudding project keeps its architecture (e.g. `python + fastapi + modular`), so `add db` and the built-in `add endpoint` keep working in projects generated from it.

### Custom Endpoints

Fill in the `endpoint` field of `project.crud` to make `crudding add endpoint` and `crudding remove endpoint` follow your own structure. The field points to an endpoint that already exists in the project and works as the model:

```json
"endpoint": {
  "name": "item",
  "files": ["internal/item/handler.go"],
  "register": ["cmd/api/main.go"]
}
```

- `name` is the model endpoint, in snake_case.
- `files` are its files. `crudding add endpoint invoice` copies them, replacing the model's name in paths and contents in four forms: snake_case (`item` → `invoice`), kebab-case, PascalCase (`Item` → `Invoice`) and camelCase. Plurals follow along (`items` → `invoices`). For a one-word model name, snake_case, kebab-case and camelCase are the same string, so the new name's snake_case is used. Every path must contain the model's name, otherwise the copy would land on the original.
- `register` lists shared files such as routers and imports. Every block of consecutive lines that mentions the model is repeated right after itself with the new name (`item.Register(mux)` → `invoice.Register(mux)` below it). Lines of other endpoints whose names contain the model's (`order_item` when the model is `item`) are left alone. Since this works line by line, keep each registration on its own line.
- `crudding remove endpoint invoice` deletes the copies, the folders that became empty and the repeated lines. The model endpoint itself cannot be added or removed.
- This field is the only thing `add endpoint` and `remove endpoint` use. You can point it to a different model endpoint in any project, including the ones generated by crudding.

The name replacement is plain text, so choose a distinctive model name: with `user` as the model, `username` would also become `invoicename`.

## Project Structure

```text
cmd/crudding/                    application entry point
cmd/genall/                      generate all supported combinations
internal/generator/              generation dispatcher
internal/generator/common/       shared helpers
internal/generator/custom/       project templates (crudding init / crudding template)
internal/generator/langs/        language-specific generators
internal/manifest/               project.crud manifest handling
internal/project/                project configuration, naming, and slug
internal/test/                   internal unit and integration tests
internal/tui/                    interactive terminal menu
templates/                       templates embedded into the binary by assets.go
```
